## SUMMARY
DeepSeek-V2 MLA와 ITME는 데이터센터·클라우드 장문맥 서빙의 KV cache 병목을 서로 다른 계층에서 완화한다. MLA는 캐시 표현을 작게 만드는 모델 구조이고, ITME는 CXL·DRAM·NVMe 계층으로 누적 상태를 확장하는 시스템이다. 공개 근거 기준 성숙도는 MLA를 TRL 8~9, ITME를 TRL 5~6으로 추정한다. 이는 공식 인증이나 실측 결과가 아니다. [1, p.1] [2, p.8] [W1]

MLA는 공개 모델·서비스와 서빙 생태계가 확인되지만 기존 모델에 그대로 붙일 수 없고 최적화된 실행 환경이 필요하다. ITME는 원격 메모리와 prefix 재사용의 가능성을 실증했지만 FPGA의 캐시 미스·경합과 개별 기술의 상용 채택 근거가 한계다. 시장의 효율·확장 기대와 실제 운영의 호환성·지연·비용 조건이 엇갈린다. 두 기술의 단순 우열은 판정하지 않으며, 결합 효과도 검증 전에는 가정으로 남긴다. [1, p.6] [2, p.9] [2, p.11] [W2]

## 1. 분석 배경
### 1.1 평가 범위
본 보고서는 판교 9반 2조의 설계에 따라 SW 기술 DeepSeek-V2 MLA와 HW 기술 ITME를 기술 성숙도, 시장성, 이해관계자, 도메인 적용성으로 비교한다. 대상 환경은 데이터센터·클라우드 기반 장문맥 LLM 서빙이다. 자료 확인 기준일은 2026-09-22이며, 논문 인용 페이지는 제공된 PDF의 첫 페이지를 1로 센 번호다.

KV cache는 이전 토큰의 Key·Value를 재사용하여 반복 계산을 줄이지만, 문맥과 동시 요청이 늘수록 메모리 부담을 키운다. MLA는 저장 표현을 압축하고, ITME는 원격 계층에 상태를 보존하여 폐기·재계산을 줄이는 방향이다. 동일 병목을 다루더라도 모델·서버·워크로드가 다른 실험 수치를 직접 경쟁 점수로 바꾸지 않는다. [1, p.6] [2, p.1]

### 1.2 규모와 평가 질문
캐시 규모를 설명하기 위한 계산 예시로, 80개 레이어·8개 KV head·head dimension 128·FP16을 가정하면 토큰당 KV는 2×80×8×128×2 = 327,680 bytes, 즉 320 KiB다. 아래는 이 가정의 산술값이며 실측 성능이나 특정 서비스의 실행 가능성을 뜻하지 않는다. 가중치·활성값·런타임 여유 메모리는 제외했다.

| 문맥 길이 | 요청 1건의 KV | 동시 요청 8건의 KV |
| --- | --- | --- |
| 8,192 tokens | 2.5 GiB | 20 GiB |
| 131,072 tokens | 40 GiB | 320 GiB |
| 1,048,576 tokens | 320 GiB | 2,560 GiB |

평가 질문은 “누가 더 우수한가”가 아니라 “같은 메모리 문제를 푸는 두 접근이 성숙도·시장·발언 주체·운영 조건에 따라 어떻게 다르게 평가되는가”이다. 모든 판단은 저자 보고, 공식 발표, 본 보고서의 해석, 확인되지 않은 사항을 구분한다.

## 2. 기술 선정
### 2.1 선정 방식과 이유
기술은 팀이 직접 선정하는 Human 기반 방식을 따른다. MLA는 모델 구조 변경을 통한 KV 축소의 대표 사례이고, ITME는 CXL-hybrid 원격 메모리를 통한 확장의 사례여서 비교 축이 분명하다. [1, p.1] [2, p.1]

| 대상 | 선정 이유 | 적용 범위의 경계 |
| --- | --- | --- |
| DeepSeek-V2 MLA | 원문·공개 체크포인트·구현 지침으로 구조와 결과를 추적 가능 | 학습된 MLA 모델 구조의 효과를 평가. 모든 기존 모델에 적용 가능한 사후 압축으로 해석하지 않음 |
| ITME | prefix KV와 가중치의 예측 가능한 접근을 활용하는 계층 메모리 설계·실증 제공 | ITME 개별 시스템과 일반 CXL 제품·시장의 성숙도를 구분 |

### 2.2 비교 문헌 활용
기술 문서 풀은 DeepSeek-V2 52쪽, ITME 13쪽, InfiniGen 18쪽, CXL-PNM 13쪽으로 총 96쪽이다. 과제의 200쪽 한도 이내다. InfiniGen은 필요한 KV를 선택적으로 가져오는 관리 방식, CXL-PNM은 메모리 근처의 연산까지 확장하는 접근을 보여준다. 이 두 문헌을 통해 ITME를 유일한 오프로딩 해법으로 해석하지 않는다. [3, p.1] [4, p.1]

KIVI·TurboQuant 등 사후 양자화 계열은 이번 평가 대상 2건에 포함하지 않았다. 이 선택은 성능 열위 판정이 아니라 모델 구조 변경과 메모리 계층 확장에 분석 범위를 맞춘 것이다. SW 측 독립 비교 문헌은 상대적으로 적어 증거 균형의 한계로 남긴다.

## 3. 기술 개요
### 3.1 접근과 전제조건
| 구분 | DeepSeek-V2 MLA | ITME |
| --- | --- | --- |
| 핵심 접근 | Key·Value의 저차원 잠재 표현을 저장하는 attention 구조 | CXL-hybrid DRAM·NVMe 원격 계층과 소프트웨어 prefetch |
| 병목 완화 위치 | 토큰당 KV 저장량 | 계층별 용량과 상태 이동·재사용 |
| 주요 전제 | MLA 구조와 해당 가중치, 이를 지원하는 실행 경로 | CXL 장치·서버 간 연결·staging buffer·prefetch 및 스케줄링 |

| 근거 | [1, p.6] [1, p.7] [W1] | [2, p.3] [2, p.8] [2, p.11] |

### 3.2 성능 수치의 읽는 방법
DeepSeek-V2 원문은 DeepSeek 67B 대비 KV cache 93.3% 감소와 최대 생성 처리량 5.76배를 보고한다. 처리량은 모델 전체 및 구현 조건의 결과이며 MLA 하나의 독립적인 인과 효과로 단정하지 않는다. ITME 실험과 모델·환경·지표가 달라 두 숫자의 크기를 직접 비교하지 않는다. [1, p.1] [1, p.16]

ITME는 FPGA 기능 검증과 CMM 기반 성능 잠재력 평가를 구분한다. 논문은 128개 동시 대화, 최대 5턴, 대화당 최소 2,000토큰 조건에서 KV footprint가 40GB에 도달하는 구간을 평가한다. 5턴에서 재계산 기준 대비 TTFT 속도 향상 1.81배를 보고하지만, 이상적인 GPU 상주 캐시 구성은 최대 3.02배를 보여 원격 계층이 항상 더 빠른 것은 아니다. [2, p.8] [2, p.9]

FPGA의 DRAM 캐시 적중 시 평균 읽기 18GB/s·쓰기 12GB/s와 별개로, 캐시 미스 시 대역폭이 1GB/s 미만으로 저하되는 한계도 보고된다. 따라서 CMM 구성의 결과를 완성된 FPGA 제품 성능으로 동일시하지 않는다. [2, p.10] [2, p.11]

## 4. 관점별 평가
### 4.1 기술 성숙도: 공개 정보 기반 TRL 추정
TRL은 발표 문서의 종류보다 구현·검증·운용 환경을 기준으로 해석한다. 연구·개념 검증(1~3), 구성요소·관련 환경 검증과 시제품(4~6), 운영 환경 실증·시스템 완성·실제 운용(7~9)을 구분하되, NASA의 우주 분야 정의를 LLM 서빙에 맞게 적용한 평가자 해석이다. [W7]

| 기술 | 추정 | 판정 근거 | 확정하지 못한 범위 |
| --- | --- | --- | --- |
| MLA | TRL 8~9, 신뢰도 중간 | 원문 실험, 공개 가중치·추론 경로, 공식 V2 웹·API 제공 안내 [1, p.1] [W1] | 운영 규모·장애율의 독립 감사가 없어 특정 환경의 TRL 9를 보증하지 않음 |
| ITME | TRL 5~6, 신뢰도 중간 | 실제 서버 환경, FPGA 시제품, CMM 성능 평가 [2, p.8] [2, p.11] | 이번 조사에서 ITME 개별 제품의 고객 운용·상용 배포를 입증할 자료 미확보 |

DeepSeek 후속 모델의 AWS·NVIDIA 제공은 계열 생태계의 보조 근거다. 이를 V2 자체의 모든 운영 조건으로 옮기지 않는다. 마찬가지로 SK hynix의 CXL 전시·클라우드 적용 사례를 ITME의 채택 사례로 바꾸지 않는다. 논문 발표와 실제 채택에는 시차가 있으므로 미확인 상태를 “상용화가 없다”는 사실로 단정하지 않는다. [W3] [W4] [W5]

MLA의 시장성은 독립 제품 매출보다 모델·서빙 서비스 안에서 관찰된다. ITME는 CXL 확장 생태계의 영향을 받지만 AI 메모리 전체의 성장 전망을 해당 기술의 예상 매출로 환산할 수 없다. 두 시장은 범위가 달라 숫자만으로 우열을 판정하지 않는다.

### 4.4 도메인 적용성: 공통 D1~D7

| D5 운영 안정성 | 근거 부족: 장기 장애율·꼬리 지연·다중 tenant 운영 안정성을 현재 근거로 확정 불가 | 제약: FPGA 캐시 미스 대역폭 저하·경합이 확인됨. 운영 전체의 실패를 뜻하지 않음 [2, p.11] |
| D6 도입·확장 용이성 | 조건부: MLA 모델·가중치와 최적화된 실행 경로 필요 [1, p.6] [W1] [W2] | 조건부: CXL·RDMA/NIC·계층 스케줄러 등 시스템 변경 필요 [2, p.8] |
| D7 비용 효율성 | 근거 부족: KV·처리량 이점을 동일 서비스의 TCO 절감률로 환산할 자료 부족 | 근거 부족: 용량 확장 논리는 있으나 장비·전력·운영 인력 포함 TCO 검증 부족 |

## 5. 종합 의견
### 5.1 네 관점의 일치와 차이
| 관점 | MLA | ITME |
| --- | --- | --- |
| 기술 성숙도 | 공개 구현·서비스 근거, TRL 8~9 추정 | 시제품·실증 근거, TRL 5~6 추정 |
| 시장 | 접근 가능한 생태계, 개별 시장 규모 불명확 | 인접 시장 기대, 직접 상용 채택 근거 부족 |
| 이해관계자 | 공급자·서빙 생태계의 수용과 최적화 조건 병존 | 연구진의 가능성·한계 보고, 독립 고객 시각 부족 |
| 도메인 | KV 축소 효과와 모델 전환·운영 검증 조건 병존 | 상태 수용 확장과 미스·경합·인프라 조건 병존 |

일치 지점은 다음과 같다. MLA에서는 원문 효율 개선과 구현 생태계의 지원이 메모리 효율이라는 방향에서 맞닿는다. ITME에서는 원문 확장 실증과 공급사의 CXL 활용 움직임이 메모리 계층 확장이라는 방향을 공유한다. 다만 후자는 인접 기술의 일치이며 ITME의 고객 채택을 뜻하지 않는다. [1, p.6] [2, p.8] [W1] [W4]

### 5.2 관점 간 상충과 긴장
아래는 근거를 연결한 평가자의 관점 비교다. 서로 다른 주체가 상대방을 직접 반박했다는 의미는 아니다. 직접 반대 발언이 없는 경우에는 기술·시장·운영 사이의 긴장으로만 해석한다.

| 기술·쟁점 | 관점 A | 관점 B | 엇갈리는 이유·근거 |
| --- | --- | --- | --- |
| MLA: 사용 가능성과 전환 용이성 | 시장: 공개 모델·서비스·실행 지침이 접근성을 높임 | 도메인: 기존 모델을 유지한 채 적용하는 일반 플러그인과 다름 | 이용 경로의 존재와 모델 구조 변경 비용은 다른 문제 [W1] [1, p.6] |
| MLA: 효율과 시스템 복잡도 | 기술: KV 축소로 메모리 효율 기대 | 개발자: 최적 성능은 실행 경로·커널 조건에 의존 | 저장량 절감이 모든 환경의 실행 간소화로 이어지지 않음 [1, p.1] [W1] [W2] |
| ITME: 확장 기대와 지연 안정성 | 기술·인접 시장: 대용량 메모리 계층의 활용 가능성 | 도메인: 캐시 미스·경합 시 FPGA 대역폭 저하 | 용량 확대와 지연 안정성은 독립적으로 검증 필요 [2, p.8] [2, p.11] [W4] |
| ITME: 생태계 활동과 개별 성숙도 | 시장: CXL 전시·클라우드 적용 움직임 | TRL: ITME는 이번 근거에서 시제품·실증 수준 | 계열 제품의 활동을 개별 연구 기술의 운용 성숙도로 전이할 수 없음 [W4] [2, p.8] |

### 5.3 두 접근의 관계
MLA는 캐시의 표현 크기, ITME는 상태의 저장 위치와 이동을 바꾸므로 개념적으로 보완 관계가 가능하다. 그러나 제공된 근거에는 MLA와 ITME를 함께 적용한 동등 조건 실험이 없다. 결합 시 캐시 형식·블록 관리·prefetch·대역폭 조건이 달라질 수 있으므로 성능 향상을 곱하거나 합산하지 않는다. 이는 구조 비교에 근거한 가능성 해석이며 실증 결론이 아니다. [1, p.6] [2, p.3]

## 6. 시사점
### 6.1 이해관계자별 도입 전 확인사항
| 담당 관점 | 확인할 질문 | 필요한 증거 |
| --- | --- | --- |
| 모델·서비스 개발 | MLA 전환 후 실제 업무 정확도와 문맥 유지가 충족되는가? | 기존 모델과 동일 업무·품질 기준의 평가 |
| 서빙·플랫폼 | 동일 장비에서 처리량과 TTFT·p95/p99 지연이 어떻게 달라지는가? | 문맥·동시성·배치·캐시 적중률을 고정한 반복 측정 |
| 인프라 운영 | ITME의 미스·쓰기 경합·장애 복구에서 서비스 목표를 지키는가? | 최악 조건과 장기 운용 로그 |
| 구매·재무 | 절감되는 자원이 추가 장비·전력·운영 비용보다 큰가? | 동일 서비스량 기준 전체 비용 명세 |
| 기술 평가 | 개별 기술의 채택과 기술 계열의 발표를 구분했는가? | 제품명·버전·고객·운용 환경이 연결된 1차 자료 |

### 6.2 중립적 결론
MLA의 효율·생태계 근거는 기존 모델 전환의 쉬움을 자동으로 뜻하지 않는다. ITME의 대용량 확장 가능성도 모든 접근 패턴의 낮은 지연을 뜻하지 않는다. 도입 판단에 필요한 것은 통합 순위가 아니라, 목표 서비스의 제약과 각 기술의 전제조건을 맞추는 작업이다. 본 보고서는 기술 추천이나 승자를 제시하지 않는다.

## 7. 한계점
### 7.1 공개 정보와 평가 범위
모든 TRL은 논문·공개 구현·기업 발표에 근거한 추정이며 공식 인증이 아니다. 기술 발표와 실제 채택의 시차, 공개되지 않은 내부 검증으로 실제 성숙도와 차이가 날 수 있다. 성능 수치는 원문 저자의 보고이며 이 팀이 동일 장비에서 재현한 결과가 아니다.

이번 확인 범위에서는 MLA·ITME 전용 시장 규모, 독립 고객의 장기 운영 결과, ITME 직접 투자 평가, MLA+ITME 결합 실험을 충분히 확보하지 못했다. 찾지 못한 자료는 존재하지 않는다고 단정하지 않는다. 기업 발표와 기업 뉴스룸에 실린 인터뷰는 이해관계와 편집 선택의 영향을 받을 수 있다.

### 7.2 확증편향 방지와 근거 균형
| 증거 유형 | MLA | ITME | 해석 제한 |
| --- | --- | --- | --- |
| 직접 기술 원문 | DeepSeek-V2 | ITME | 저자 실험과 독립 재현을 구분 |
| 비교 원문 | 이번 문서 풀에서는 제한적 | InfiniGen·CXL-PNM | 문서 수 차이를 우열 점수로 사용하지 않음 |
| 웹 근거 | 공식 구현·커널, 후속 모델 서비스 | CXL 계열 전시·응용, AI 메모리 인터뷰 | 계열 정보를 개별 기술의 직접 증거로 전환하지 않음 |
| 부정·한계 근거 | 실행 경로 차이, 모델 변경 전제 | FPGA 미스·경합 한계 | 확인된 제약과 일반적 우려를 구분 |

양쪽에 동일한 네 관점과 D1~D7을 적용했고, 수치마다 비교 조건을 구분했다. 종합 단계에는 앞에서 확인한 근거만 사용했다. HW 비교 문헌을 반영했으나 SW 독립 검증 자료의 부족은 해소되지 않았으므로 남은 편향 위험으로 공개한다.

### 7.3 작성 경로와 자동화 검증 상태
이 PDF는 최종 보고서를 우선 제공하기 위해 제공 논문과 별도로 확인한 공개 자료를 바탕으로 작성한 문헌 평가본이다. 프로젝트 자동 파이프라인은 임베딩 색인까지 실행했으나 외부 웹 검색 API의 HTTP 429 요청 제한으로 중단되었다. 따라서 이 파일은 LangGraph 전체 실행·자동 Judge 통과의 증거가 아니다. 기술 평가 내용과 개발 산출물의 실행 재현성 평가는 분리해야 한다.
