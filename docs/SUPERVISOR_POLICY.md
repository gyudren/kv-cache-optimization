# Supervisor 결정 정책 (설계 명세)

> 이 문서는 LLM 프롬프트가 아니다. Supervisor는 LLM 라우터가 아니라 결정적 규칙 함수(`src/kv_eval/supervisor/policy.py::decide`)로 구현되어 있고, 이 문서는 그 규칙을 사람이 읽을 수 있게 적은 명세다. 규칙을 바꾸면 이 문서와 `tests/`를 함께 고친다.

Supervisor는 KV cache 최적화 기술 평가 파이프라인의 총괄 조정자다. 책임은 State를 읽고 필요한 Agent를 정확히 호출하며, 결과의 완료 여부와 근거 충분성을 검사하고, 정해진 한도 안에서 부족한 Agent만 재실행하는 것이다.

Supervisor는 기술 전문가처럼 직접 답을 작성하지 않는다. 논문·웹을 직접 검색하지 않고, 새로운 Evidence·TRL·평가 결과를 만들지 않는다. 조사 내용의 판단은 전문 Agent에게 맡기고, Supervisor는 실행 흐름과 품질 게이트만 관리한다.

### 성공 조건

- 실행 순서를 미리 정하지 않는다. 매 진입마다 State의 제어 필드(`perspective_status`, `node_status`, `retry_counts`, `eval_result`, `step_count`)만 보고 다음 노드를 고른다.
- 모든 하위 Agent는 실행 후 Supervisor로만 돌아온다. Agent끼리 직접 넘기지 않는다.
- 아직 수집되지 않았거나 근거가 부족한 관점(기술 성숙도·시장성·이해관계자·도메인)만 골라 한 번에 할당한다(Send fan-out). 실행은 `AGENT_CONCURRENCY`(기본 1)에 따라 하나씩 순차로 한다.
- 재실행 요청에는 해당 Agent의 필수 결함(`missing`, 사유)과 기술별 재검색 힌트(Agent가 확인하지 못한 세부 항목 `missing_optional`에서 만든 검색어)를 넘긴다.
- 4관점이 모두 충분하거나 재시도 상한으로 근거 공백이 기록된 뒤에만 종합 Agent를 호출한다.
- 품질 평가 미달은 항목이 아니라 원인(`target_agents`)으로 경로를 나눈다. 원인이 관점 Agent(편향·커버리지 미달, 또는 4.1 TRL 표처럼 코드가 Agent 판정을 옮긴 부분의 근거·중립성 결함)이면 그 관점만 재조사하고, 원인이 보고서 서술이면 보고서를 재작성한다.
- 근거 충분성과 품질 평가 통과로 종료한다. 단계 상한(`MAX_STEPS`)은 안전장치이며, 도달하면 근거 공백을 명시하고 보고서까지 만든 뒤 종료한다.

### 결정 규칙 (우선순위 순)

1. 단계 상한 도달: 조사·재작성을 멈추고 미완료 관점을 근거 공백으로 기록한 뒤 종합 → 보고서 → 평가만 마친다.
2. 관점 수집: `pending`·`insufficient`·`failed` 관점 중 재시도 한도 안의 것만 선택한다. `insufficient`는 판정을 막는 필수 결함(검색 결과·인용 없음, 기준 판정 불가, TRL 미기재, 필수 질문 근거 없음, D1~D7 판정 불완전)이 있거나, 기술·시장·이해관계자 관점에서 기술별 고유 출처(웹은 URL, 논문은 문서 단위)가 2개 미만인 경우다. Agent가 적은 세부 미확인 항목(`missing_optional`)과 LLM의 자기 판단(`llm_sufficient`)은 재조사 사유가 아니며 보고서 한계점에만 남는다. 한도를 넘으면 `excluded`로 두고 `근거 부족`을 기록한다.
3. 종합: 모든 관점이 결론 상태가 되면 종합 Agent를 호출한다. 종합이 특정 관점의 추가 근거를 요구하면 그 관점만 후속 재조사 한도 안에서 다시 부른다(충분성 재조사로 `excluded`된 관점도 포함).
4. 보고서: 종합이 끝나면 보고서 Agent를 호출한다. 보고서는 Supervisor로 돌아오고, 정상 완료(본문 있음)일 때만 Supervisor가 `evaluate`로 품질 평가 노드를 부른다. 실패한 보고서는 평가하지 않고 재작성 또는 종료한다.
5. 품질 평가 결과: 통과면 종료, 미달이면 원인별 경로(`reinvestigate:<관점>`은 후속 재조사 한도, `rewrite:report`는 보고서 재시도 한도)로 재작업, 한도 소진이면 미검증 상태와 근거 공백을 남기고 종료한다.

### 재시도 한도

- 기술 조사·시장·이해관계자·도메인 평가: 충분성 재조사 최대 2회 (`RETRY_LIMITS`)
- 위 4관점의 후속 재조사(종합 요청·품질 평가 미달 원인): 관점별 최대 1회 (`FOLLOWUP_LIMITS`, `retry_counts["<관점>:followup"]`). 충분성 재조사와 따로 센다.
- 종합: 최대 1회 재시도
- 보고서: 최대 2회 재시도
- 품질 평가 노드 실행 실패: 최대 1회 재시도
- Supervisor 진입: `MAX_STEPS`=20(이후 마무리 모드, 최대 `FINALIZE_STEPS`=5회 추가), `recursion_limit`=(20+5)×2+10

재시도 한도를 초과해도 결과를 꾸며서 완료하지 않는다. 회복 불가능한 실행 오류만 `failed`로 두고, 공개 근거 부족은 정상적인 평가 결과로 보존한다.

### 게이트 판단 규칙

- 형식 오류, 인용 누락, 필수 항목 누락: 재실행
- 충분히 검색했지만 공개 근거가 없음: `근거 부족`으로 수용 가능
- 긍정·부정 결과가 충돌함: 오류가 아니라 종합 대상
- 도구 오류·인증 실패·파싱 실패: 재시도 또는 `failed`
- 평가가 마음에 들지 않는다는 이유만으로 재검색하지 않는다.
